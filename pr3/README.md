## 1. Тема роботи

Написання тест-кейсів для перевірки програмного забезпечення.

## 2. Мета роботи

Закріпити теоретичні знання та розвинути практичні навички з роботи QA/QC, створення чітких, лаконічних, атомарних і незалежних тест-кейсів, а також інтерпретації результатів виконання тестів.

## 3. Короткі теоретичні відомості

Тест-кейс — це структурований опис перевірки певної функції програмного продукту. Він визначає початковий стан системи, послідовність дій, очікуваний і фактичний результати.

Класичний тест-кейс містить:

* **ID** — унікальний ідентифікатор;
* **назву** — короткий опис перевірки;
* **пріоритет** — High, Medium або Low;
* **передумови** — стан системи перед початком тесту;
* **кроки** — послідовність дій;
* **очікуваний результат** — поведінка, яка відповідає вимогам;
* **фактичний результат** — результат виконання перевірки;
* **статус** — Pass, Fail або Blocked.

Правила створення тест-кейсів:

1. **Атомарність** — один тест-кейс перевіряє одну логічну функцію.
2. **Незалежність** — виконання тесту не залежить від результату попереднього тесту.
3. **Чіткість** — усі кроки та результати сформульовано однозначно.
4. **Відтворюваність** — тест може повторити інша людина.
5. **Конкретність** — використовуються визначені тестові дані.

Можливі результати:

* **Pass** — фактичний результат відповідає очікуваному;
* **Fail** — фактичний результат не відповідає очікуваному;
* **Blocked** — виконання тесту неможливо продовжити.

Репозиторій проєкту:

# 8. Відповіді на контрольні питання

## 1. Навіщо потрібні тест-кейси?

Тест-кейси потрібні для структурованої та повторюваної перевірки функцій програмного продукту. Вони допомагають знаходити помилки, перевіряти відповідність вимогам і контролювати якість після внесення змін.

## 2. Які основні атрибути тест-кейсу?

Основними атрибутами є:

* ID;
* назва;
* пріоритет;
* передумови;
* кроки;
* очікуваний результат;
* фактичний результат;
* статус виконання.

Додатково можуть зазначатися тип тесту, компонент, тестові дані та постумови.

## 3. Які типи тест-кейсів існують?

Основними типами є:

* позитивні;
* негативні;
* функціональні;
* нефункціональні;
* інтеграційні;
* регресійні;
* тест-кейси безпеки;
* тест-кейси продуктивності.

## 4. Що таке негативний тест-кейс?

Негативний тест-кейс перевіряє реакцію системи на неправильні, неповні або недопустимі дані. Тест вважається успішним, якщо система відхиляє некоректні дані, не завершує роботу аварійно та показує зрозуміле повідомлення.

Прикладом є авторизація з неправильним паролем або спроба повторної реєстрації з уже використаною електронною адресою.

У межах навчального тестового сценарію всі десять тест-кейсів завершилися зі статусом `Pass`. Фактичні результати відповідали очікуваним, а негативні сценарії підтвердили належну реакцію системи на некоректні дані.

На основі проведеної роботи було ініційовано подальше вдосконалення проєкту, розширення автоматизованого тестування та покращення процесу перевірки програмного забезпечення.

Мету практичної роботи досягнуто: отримано практичні навички створення, оформлення та інтерпретації результатів виконання тест-кейсів.
